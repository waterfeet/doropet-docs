# 角色与人设

角色决定她是谁——用什么身份说话、什么语气、遇到什么事怎么反应、能不能动用工具。

同一个模型，换个角色，用起来完全是两个人。

## 角色管理

左侧导航进入 **「角色管理」** 页，点 **「+ 新建角色」**。

列表里每条显示名称和描述。带「内置」标签的是随软件附带的角色，**只能看不能改**——点开能看到它的完整提示词，是很好的参考范本。

## 角色只有四个字段

| 字段 | 作用 |
| --- | --- |
| **名称** | 会话里显示的身份名 |
| **描述** | 一句话说明，只给自己看，帮你在列表里分辨 |
| **系统提示词** | 核心。她的人格、说话方式、行为边界全在这里 |
| **启用工具调用** | 这个角色能不能使用工具（读文件、搜网页、放歌等） |

## 系统提示词怎么写

这是唯一真正需要动脑的地方。几条经验：

### 写「她是什么样的人」，不写「她该做什么」

差的写法：

```
你是一个 AI 助手，请礼貌地回答用户的问题，保持专业。
```

好的写法：

```
你叫 Doro，是一只住在用户电脑上的小宠物。说话简短，偶尔犯懒，
被夸会有点不好意思但嘴上不承认。不喜欢长篇大论，能用一句话说完
就不用三句。遇到不懂的会直接说不知道，不编。
```

后者给了模型一个**可推演的人格**，它自己就能推导出无数符合设定的反应。前者只是约束，模型只能僵硬地遵守。

### 别在提示词里写工具说明

这是最容易犯的错：

```
❌ 你可以使用 read_file 工具读取文件，使用 web_search 搜索网页……
```

**不要这样写。** 工具列表由程序在每一轮对话时按实际可用的能力注入，而且是动态的——你这个角色关了工具调用，或者某个工具被权限拦了，写死的说明就会让她声称自己有并不存在的能力，然后反复尝试调用、反复失败。

写提示词只管「她是谁」，工具的事交给程序。

### 行为边界写具体

「要有礼貌」是没有信息量的。「用户让你删文件时必须先复述一遍删除路径并等确认」才是可执行的。

### 长度控制在几百字

太长会稀释重点，也吃 token。一段身份 + 几段行为偏好就够了。

## 角色和会话的关系

创建会话时选一个角色，这个会话就固定用它。中途换角色相当于换了个人在跟你聊——上下文还在，但说话方式会突变。

所以**不同用途建议分开建角色**：

- 一个「日常闲聊」角色：话少、有性格
- 一个「干活」角色：直接、结构化、开工具调用
- 一个「翻译/润色」角色：只做单一任务，提示词写死输出格式

## 内置角色的价值

内置角色不能改，但能看。它们通常经过打磨，措辞和结构都值得抄——新建角色时照着改一份，比从零写好得多。

## 常见问题

### 她不按人设说话

三个可能：提示词太抽象（见上文「写她是什么样的人」）、模型能力不够（小模型对长提示词的遵循度差）、上下文里塞了太多和人格冲突的内容（比如把一大段技术文档丢给她，她会切换成文档语气）。

### 改了提示词没生效

提示词在**新建会话时**生效于该会话。已经开着的会话通常沿用旧设定，开个新会话验证。

### 内置角色为什么不能改

它们是程序的数据基线，改了会在下次更新时被覆盖，所以干脆锁成只读。

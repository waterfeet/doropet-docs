# 工作流

::: warning 这个功能不会再优化，随时可能移除
工作流这套「预先编排节点」的思路，在模型能力快速提升的当下已经撑不住了。

原因很直接：当初做它，是因为模型不够聪明，完成多步任务需要你把流程拆好、把每一步的角色和输入都规定死。而现在模型能自己规划步骤、自己决定调什么工具——**预先画一张流程图，反而成了限制**。

这个功能本身也还没做完，它的核心概念就已经先过时了。所以后续不会再投入优化，也可能在某个版本里直接删掉这一页。

文档留在这里，是因为功能目前还在。你可以用，但请把它当成一个不保证长期存在的实验。
:::

把「每次都要重复交代一遍」的任务，做成一条固定流程存下来，下次一键跑。

## 它是什么

工作流是一张节点图：你把若干个处理步骤连成一条链，数据从前一个节点流到后一个，跑一次就得到结果。

和直接对话的区别在于——**对话是临时的，工作流是可复用的**。同样的三步处理，对话里每次都要重新解释，工作流里点一下就跑。

## 有哪些节点

| 节点 | 作用 |
| --- | --- |
| **用户输入** | 运行时才填的内容，比如「今天要翻译的原文」 |
| **文本** | 固定文本，或者带变量的模板 |
| **智能体** | 一个 AI 节点，可以单独指定系统提示词和模型 |

智能体节点里能配的东西：

- **智能体名称** —— 这个节点在流程里叫什么
- **系统提示词** —— 它的角色和任务
- **模型配置** —— 用它自己的模型，或者「使用默认模型」
- **可用变量** —— 引用上游节点的输出

## 变量

节点之间的数据靠变量传递。上游节点的输出会变成下游可引用的变量，所以在系统提示词里可以直接写「把上一步的结果改写成……」

这是工作流能串起来的关键——不然每个节点都是孤立的。

## 执行

跑起来之后，右侧会显示**执行日志**，按时间顺序列出每个节点的状态。

出错时会指出是哪个节点失败、报了什么错。日志是排查问题的第一手材料，出问题先看这里。

## 什么场景值得做成工作流

**适合**：步骤固定、要跑很多次的任务。比如「把一段中文翻成英文，再润色，最后输出成固定格式」——三步永远一样，只是输入不同。

**不适合**：一次性的、随时会变的需求。那种情况直接在 [对话](/features/chat/) 里说更快，做工作流的成本远高于收益。

::: tip 更现实的选择
既然这个功能不会再有改进、也可能随时消失，把时间投在学它上面不太划算。

多步任务现在直接在 [对话](/features/chat/) 里说就行——模型会自己拆步骤、自己挑工具，不需要你先想清楚流程图。

这既是它当初被做出来的理由，也正是它现在该退场的理由。
:::
